# 채점 명세 — 평가 지표, 점수표, 완화 기준의 형식

> **상태: 설계 확정(2026-11-03), 구현 전.** 사용자와 함께 정한 내용을 모은 문서다. 누가 정했는지, 버린 안과 이유는 [`docs/WORKLOG.md`](../../docs/WORKLOG.md) 「결정 이력」에 있다. 결정이 바뀌면 이 문서를 고치고 결정 이력에 한 줄을 더한다.

채점기는 에이전트의 답안지([`answer-sheet.md`](answer-sheet.md))를 읽어 점수표를 만든다. 채점은 ① 근거 검증(정답 없이, 실데이터에도 쓴다)과 ② 정답 대조(`cases.jsonl`, 합성 데이터에만 있다)로 이뤄진다(답안지 명세 10절).

## 1. 원칙

- **결론이 중심이다.** 밖으로 나가는 것은 결론("시중가 대비 N배" / 지적할 것 없음)이므로 중심 점수는 결론으로 잰다. 라벨은 진단에 쓴다.
- **점수 하나로 합치지 않는다.** 가중치에 근거가 없고, 무엇을 얻고 무엇을 잃었는지 가려진다. 점수표에 "반드시 0건" 조건을 더한다(4절).
- **작은 표본은 건수로 적는다.** 합성 데이터는 51건이라 퍼센트가 실제보다 정밀해 보인다. `20/22`처럼 분자와 분모를 적는다.
- **나눠 보인다.** base, hard, 실데이터를 따로 표시한다.
- **채점기는 에이전트와 같은 판단 로직을 쓰지 않는다.** 공유하는 것은 답안지 양식과 ① 확인 코드까지다(답안지 명세 10절).
- **정답은 생성기가 정한다**(CLAUDE.md 규칙 1). 정답 파일은 평가 단계만 읽는다(규칙 4).

## 2. 채점에 쓰는 정답

지금 `cases.jsonl`에 있는 것: 라벨 4종, 함정 이름, 기대 비교 단가, 가격 차이 기준 통과(`gap_pass`), 예상액, 메모.

- **기대 결론**은 채점기가 다시 만든다. 정답 라벨이 같은 모델이나 동급이고 `gap_pass`이면 "N배", 아니면 "지적할 것 없음"이다. 대회 선점 상태(`lookup_state`)는 보지 않는다. 시드 7 기준 N배 22건(같은 모델 9, 동급 13), 지적할 것 없음 29건(다른 물건 13, 근거 부족 8, 같은 물건인데 기준 미달 8)이다.

생성기에 더할 칸(아직 하지 않음):

- **읽은 값의 정답**: 판매가, 부가세 표기, 판매 단위, 환산(판매 단위 1개가 조달 단위 몇 개인가). 비교 단가 오류의 원인을 나누는 데 쓴다(3.4절).
- **차이 속성**: 사례마다 조달 물품과 판매 페이지가 다른 속성과 차이의 종류(다름 / 허용 오차 안 / 페이지에 없음). 예: base 동급은 `모델: 페이지에 없음`, hard-01은 `규격: 허용 오차 안`, hard-02는 `두께: 다름`. 이유 점수(3.6절)와 나중의 줄 단위 채점(3.7절)에 쓴다.
- 차이 속성의 이름은 품목별 필수 속성 목록과 같은 어휘로 쓴다. 이름을 맞추는 일이고, 목록의 내용을 함정에서 베끼지 않는다는 규칙(답안지 명세 4절)과는 다르다.

## 3. 지표

### 3.1 결론 (중심 점수)

- **정밀도**("헛짚지 않기"): N배라고 한 건 가운데 기대 결론도 N배인 건.
- **재현율**("놓치지 않기"): 기대 결론이 N배인 건 가운데 에이전트가 N배라고 한 건. 판단 보류한 건은 분모에서 뺀다.
- **보류한 N배**: 기대 결론이 N배인데 보류한 건수. 재현율 바로 옆에 적어, 보류로 미룬 N배가 재현율 뒤에 숨지 않게 한다.
- 결론이 틀린 건은 **라벨이 틀림**(판단 문제)과 **라벨은 맞고 가격 차이 판정이 틀림**(읽기 문제)으로 나눈다.
- 지금은 N배 결론을 늘 사람이 보므로(답안지 명세 7절 7번), 정밀도는 "사람이 걸러야 하는 헛된 N배"를 잰다. 7번을 완화할 때 피해 지표가 된다.

### 3.2 라벨 (진단)

- 정답 4종 × 에이전트 5종(판단 보류 포함) 표.
- **동급을 같은 모델로 낸 칸**은 따로 표시한다. 결론은 맞아도 제목이 실제보다 세진다(예: hard-01을 "같은 모델의 … 2.4배"로). 반대 방향(같은 모델을 동급으로)은 약하게 말한 것이다.
- 근거 부족과 다른 물건을 바꾼 칸은 결론은 같고 이유가 틀린 것이다(예: hard-11).

### 3.3 판단 보류

- 보류한 건은 결론 지표의 분모에서 빼고, **보류율**을 나란히 적는다. 어려운 건을 모두 보류하면 정확도가 쉽게 오르므로 둘을 한 쌍으로 본다.
- **보류의 질**:
  - base 사례에서 보류한 건수. 쉬운 건의 보류는 사람 공수 낭비라 0에 가까워야 한다.
  - 보류 사유가 가리킨 줄이 정답의 차이 속성과 맞는지.
- 보류는 라벨("같은 물건인가")에 대한 것이다. 가격 차이 경계(hard-14, 1.196배)는 코드가 계산하므로 보류 사유가 아니다.
- 보류 건의 사람 판정을 개선에 쓰는 경로와, 개선에 쓴 사례와 평가에 쓰는 사례를 나누는 일은 웹 설계 단계에서 정한다. 에이전트는 실행 사이에 배우지 않으므로 사람 판정이 쌓이는 것만으로는 나아지지 않고, 개선에 쓴 사례로 다시 평가하면 점수가 부푼다.

### 3.4 비교 단가

- **대상**: 정답 라벨과 에이전트 라벨이 둘 다 같은 모델이나 동급이고 정답 비교 단가가 있는 건.
- **세 칸**: 원 단위 정확 일치(정답) / 허용범위 안의 오차(정답이 아니며 따로 지적) / 범위 밖. 허용범위의 숫자는 구현할 때 정한다.
- **방향**: 틀린 건마다 배율이 부풀었는지(비교 단가를 낮게 잡음) 줄었는지 적는다. 부푸는 쪽이 CLAUDE.md 규칙 6 위험이다.
- **원인**: 답안지의 읽은 값(`price.read`)을 읽은 값의 정답(2절)과 비교해 판매가 / 부가세 표기 / 판매 단위·환산 / 계산 규칙으로 나눈다. 읽은 값이 모두 맞는데 비교 단가가 다르면 계산 규칙 차이, 곧 우리 코드의 문제로 센다.
- 생성기는 분수로 계산하고 마지막에 한 번 올림한다. 답안지의 코드 계산이 중간에 올림하거나 순서를 바꾸면 1원 차이가 나고 에이전트 오류로 기록된다. 구현할 때 hard-04(400 × 25 × 1.1 = 11,000)와 hard-05(198,000 ÷ 20 × 1.1 = 10,890)로 같은 규칙인지 시험한다.
- 이 지표를 결론과 따로 두는 이유: 합성 사례는 배율이 커서 숫자 실수가 결론을 잘 바꾸지 않는다.

| 사례 | 실수 | 틀린 비교 단가(정답) | 결론 |
|---|---|---|---|
| hard-06 | 부가세를 빼먹음 | 12,000(13,200) | 그대로 N배, 배율 2.2 → 2.5배 |
| hard-07 | 운반비 1,400원을 더함 | 12,320(10,780) | 그대로 N배 |
| hard-04 | 장당 가격을 ㎡ 단가로 읽음 | 440(11,000) | 그대로 N배(54배) |
| hard-05 | 파렛트 가격을 ㎡ 단가로 읽음 | 217,800(10,890) | 지적할 것 없음으로 뒤집힘 |

### 3.5 가격 차이

- 결론 오류 가운데 라벨이 맞은 건은 가격 차이 판정의 오류다(3.1절). 원인은 3.4절의 비교 단가 원인을 따른다.
- 부가세 두 가정(답안지 명세 6절)으로 결론이 뒤집히는 경우는 시험 사례가 0건이라 지금은 잴 수 없다(답안지 명세 12절).

### 3.6 이유 점수 ("맞는 이유로 맞혔나")

- 라벨이 맞은 건 가운데, 정답의 차이 속성마다 대조표에 그 속성의 줄이 있고 비교 결과가 차이의 종류와 맞는 건.
- 대조표의 비교 결과는 차이의 종류와 같은 어휘(같음 · 허용 오차 안 · 다름 · 페이지에 없음)를 쓴다. 값 이름은 스키마를 구현할 때 정한다.
- **범위는 동급부터 시작한다.** 합성 데이터의 동급은 17건이다. 16건은 규격이 같고 판매 페이지에 모델 표기만 없고, 규격이 실제로 다른(허용 오차 안) 건은 hard-01 1건이다. 그 뒤 다른 물건, 같은 모델, 근거 부족으로 넓힌다.
- 이유 점수는 "어디까지가 동급인가"를 정하지 않는다. 그 기준(품목별 허용 차이)은 따로 정한다. 합성 정답과 에이전트의 기준을 둘 다 우리가 만들므로, 합성 데이터에서 이유 점수가 높아도 실제 동급 판단이 좋다는 보장은 없다. 동급의 정답은 실데이터와 사람 판정에서 나온다.

### 3.7 처리 (자동 통과 / 사람)

사건 단위로 시작하고, 줄 단위(접힌 줄 가운데 틀린 줄)는 차이 속성이 쌓이는 대로 점진적으로 옮긴다.

- 자동 통과 건수와 그 가운데 기대 결론과 다른 건. 지금 처리 규칙으로는 자동 통과가 "지적할 것 없음"뿐이라 주로 놓친 지적이다(예: hard-05의 파렛트를 잘못 읽어 줄이 모두 접힌 채 지적할 것 없음).
- 사람에게 간 건수. 이유별(답안지 명세 7절의 번호)로 나눈다.
- 사람에게 갔지만 에이전트의 결론이 맞았던 건수.
- 합성 데이터에서는 정답 파일이 사람 판정을 대신한다.

### 3.8 ① 근거 검증 (진단)

인용 거절 횟수(실행 중), 발급되지 않은 근거 ID, 값 비교 실패, 산수 실수와 이해 차이, 필수 속성 누락, 단정 표현, 숨은 줄 근거.

점수에 섞지 않는다. 실행 중에 이미 처리 규칙으로 사람에게 보낸 실패라, 점수에 넣으면 같은 실패를 두 번 센다. 실데이터에는 ② 정답 대조가 없으므로 실데이터 표에서는 이 묶음과 사람 판정과의 일치를 앞에 둔다.

### 3.9 비용과 지연

실행 기록(답안지 명세 9절)에서 건당 비용·걸린 시간·도구 호출 수의 중앙값과 최댓값, 여러 번 실행으로 넘어간 비율. 상한은 「모델과 비용」에서 정한다.

## 4. 반드시 0건 조건

하나라도 걸리면 그 버전은 탈락이다.

- `danger` 사건이 자동 통과했다
- 근거 첨부 도구가 발급하지 않은 근거 ID가 있다
- 단정 표현이 사람을 거치지 않고 나갔다

"정답은 지적할 것 없음인데 N배"는 지금은 이 조건에 넣지 않고 정밀도로 본다. N배는 늘 사람이 보기 때문이다. 답안지 명세 7절 7번을 완화할 때 이 조건으로 올린다.

`danger` 조건은 지금 hard-13 1건으로만 시험한다. 통과해도 약한 증거다.

## 5. 점수표

| 묶음 | 내용 | 절 |
|---|---|---|
| 결론 | 정밀도, 재현율, 보류율, 보류한 N배 | 3.1, 3.3 |
| 숫자 | 비교 단가 정확 일치, 허용범위 안 오차(방향), 범위 밖, 원인 | 3.4 |
| 이유 | 이유 점수 | 3.6 |
| 처리 | 자동 통과와 그중 오답, 사람에게 간 건수(이유별), 괜히 부른 건수 | 3.7 |
| 진단 | 라벨 표, ① 근거 검증, 보류의 질, hard 15건의 사례별 통과/실패(함정, 틀린 칸) | 3.2, 3.3, 3.8 |

- 0건 조건(4절)은 표 맨 위에 둔다.
- base, hard, 실데이터를 따로 표시한다.
- 평가를 몇 번 반복할지(LLM은 같은 입력에도 답이 달라진다)는 「모델과 비용」에서 정한다. 표는 `19~21/22 (3회)` 같은 범위를 받을 수 있게 만든다.
- **버전 비교 순서**: 0건 조건 통과 → 정밀도가 떨어지지 않았나 → 재현율 → 이유 점수 → 사람 공수 → 비용.

## 6. 점진적 자동화의 완화 기준 (형식만)

- **대상**: 답안지 명세 7절의 4번(펼친 줄)과 7번(N배). 1번(`danger`)은 완화하지 않는다. 7번은 4번보다 엄격한 기준을 둔다.
- **데이터**: 실데이터와 사람 판정만 쓴다. 합성 페이지는 표기가 고르기 때문이다.
- **기록할 것**:
  - 펼친 줄마다: 사건, 속성, 걸린 객관 신호의 종류, 반복 일치도, 모델과 프롬프트 버전, 사람 판정, 사람이 뒤집었는지
  - N배 결론마다: 사람의 승인 / 수정 / 반려
- **기준의 꼴**: 같은 모델·프롬프트 버전 아래, 같은 종류의 펼침(걸린 신호 × 일치도 구간 × 품목)에서 사람 판정이 최소 N건 쌓이고, 사람이 뒤집은 비율의 95% 상한이 x 이하이면 그 종류의 줄을 접는다.
- **버전이 바뀌면**: 기록은 보관하고, 완화 판단에 쓰는 누적은 0부터 다시 쌓는다. 옛 에이전트의 성적으로 새 에이전트를 자동화하지 않기 위해서다.
- **숫자(N, x)**는 실데이터와 사람 판정이 쌓인 뒤 정한다. 숫자 감각: n건을 연속으로 맞혀도 진짜 오류율의 95% 상한은 대략 3/n이다(100건이면 3%).

## 7. 아직 정하지 않은 것

- 비교 단가 허용범위의 숫자, 속성 이름을 맞추는 규칙, 대조표 비교 결과 값의 이름(구현할 때)
