### 그 뒤에 정할 것 (아직 다루지 않음, 순서도 미정)

- 에이전트 범위: 판매처 페이지를 **찾는 일**까지 할지, 주어진 후보 페이지를 **판정**만 할지. 찾기까지 하면 가짜 판매처에 검색이 필요하다.
- LLM과 코드의 경계: 규격 추출, 판정, 단위 환산, 부가세, gap, 인용 구간 선택을 각각 어느 쪽이 맡을지
- 도구와 권한: 에이전트가 쓸 도구 목록. 제출 도구와 토큰은 주지 않는 방향으로 이야기했다.
- 인용 정책: 원문 구간(오프셋)을 고르게 할지, 자유 텍스트로 쓰게 할지. 검증에 실패하면 어떻게 할지
- 모델과 비용: 이야기한 기본안은 Haiku 5.5로 1차 판정, 애매한 건만 Sonnet 5.5로 올리기. 한 번 실행할 때의 비용 상한, 캐시. `ANTHROPIC_API_KEY`는 환경변수나 키체인에서만 읽는다.
- 프롬프트 주입 정책(hard-13)
- 평가 지표: 판정 정밀도·재현율, 비교 단가 정확도, gap 오판율, 건당 비용·지연. 합성 점수와 실데이터 점수는 따로 표시한다.
- 1부 게이트 한계(hard-05) 처리: 게이트를 고칠지(단위 환산을 근거에 명시하면 통과), 사람에게 넘길지
- 작업 대기열·상태 전이·재시도·비용 상한(워커), 웹 화면 스택(TypeScript 쪽으로 이야기했다)

### 10/27 — 포트폴리오 판단과 1부 정리

- 제출 100건(누적 한도 전부), 수정 48건. 날짜(KST)별 신규 제출: 10/16 3, 10/17 4, 10/18 1, 10/19 20, 10/22 50, 10/23 22.

- 100건 모두 동급 비교이고 근거 출처는 한 곳(토목자재 도매몰)이다. 인조화강블록 72, 벤치플룸관 16, 옹벽 블록 5, 블랜딩블록 4, 그레이팅 덮개 3. 배율 중앙값 1.8배(최소 1.3, 최대 3.1).

### 10/28 — 2부 1단계: 데모의 바닥

- `studio/synth`: 시드 고정 합성 데이터 생성기(Python 표준 라이브러리). 기본 36개 + 어려운 사례 15개. 시드 7 기준 같은 모델 13, 동급 17, 다른 물건 13, 근거 부족 8이고, 해야 할 일은 제안 20, 제안 안 함 25, 건너뜀 6. 테스트 7개.
- `studio/fakeserver`: 가짜 대회 API와 판매처, 가짜 lint(Go 표준 라이브러리). 금액 계산은 1부 `claim.Evaluate`와 같은 규칙. 테스트 7개.
- 1부 `collector`에 데모 모드를 추가했다(설정 테스트 3개 추가). 1부의 다른 코드는 바꾸지 않았다.
- `make demo` 검증:
  - 선점 조회 → 원문 보관 → 게이트·preview → 제출 → lint `clean`이 모두 통과했다.
  - CLI가 미리 계산한 예상액과 가짜 서버 값이 32,220,000원으로 같았다(hard-01).
  - 1.196배 사례(hard-14)는 게이트가 서버에 보내기 전에 막았다.
  - 실제 `data/` 제출 기록 148건은 그대로였다.
  - PATH에 가짜 `security`를 넣어 확인한 결과, `make demo`는 키체인 호출 0회, 다른 목표는 기존대로 호출했다.
- 알려진 한계: 1부 게이트가 "비교 단가 < 관측가"를 막아 hard-05(파렛트 → ㎡)의 참조 본문을 만들지 않는다. 부가세 별도 판매가를 바르게 환산해도 게이트가 주의를 낸다(막지는 않음).
